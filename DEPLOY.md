# Deploying LeadForge for free

| Part | Where | Cost |
|---|---|---|
| Dashboard (Next.js) | Vercel, project `lead-forge-u97p` | Free |
| API (FastAPI) | Render, free plan, plain Python (no Docker) | Free |
| Keeps the API awake | Cloudflare Worker, every 10 min | Free |
| Database (Postgres) | Neon | Free, 0.5 GB |

No card is needed anywhere. Do the steps in this order and keep a notepad
open: values marked 📋 are copied into a later step.

Why the API isn't on Cloudflare itself: Cloudflare Workers can't run its
Postgres driver (asyncpg), SQLAlchemy or the Gemini SDK. Cloudflare's job here
is to keep the Render API from going to sleep.

---

## 1. Database: Neon

1. Sign up at https://neon.tech.
2. Create a project named `leadforge` in the region closest to you.
3. Click **Connect**, turn **Connection pooling off**, and copy the connection
   string, e.g. `postgresql://user:password@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require&channel_binding=require`.
   Paste it exactly as Neon gives it; the API converts any spelling
   (`postgres://`, `postgresql://`, `postgresql+psycopg://`, `sslmode`,
   `channel_binding`) to what its driver needs. 📋 **DATABASE_URL**

You don't run any SQL by hand: the API applies the migrations in
`apps/api/db/migrations` every time it starts (`python -m apps.api.scripts.migrate`).

## 2. API: Render

1. Sign up at https://dashboard.render.com with your GitHub account.
2. **New** → **Blueprint**, and connect the **LeadForge** repo. Render reads
   `render.yaml` and asks for these values:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | from step 1 |
   | `CORS_ORIGINS` | `https://lead-forge-u97p.vercel.app` (your dashboard URL, no trailing slash) |
   | `PUBLIC_API_URL` | `https://example.com` for now; you'll set the real one in 2.5 |
   | `GEMINI_API_KEY` | your key from https://aistudio.google.com |
   | `AGENCY_POSTAL_ADDRESS` | your real postal address (printed in every outreach email) |
   | `BOOTSTRAP_ADMIN_EMAIL` | the email you'll sign in with |
   | `BOOTSTRAP_ADMIN_PASSWORD` | a password of at least 12 characters |

   `JWT_SECRET` and `SERVICE_API_KEY` are generated by Render. Don't touch them.
3. Click **Apply**. The first build takes a few minutes.
4. Copy the service URL at the top, e.g. `https://leadforge-api.onrender.com`. 📋 **API_URL**
5. In **Environment**, set `PUBLIC_API_URL` to **API_URL** (it's used in the
   unsubscribe links in emails) and save. Render redeploys.
6. Open **API_URL**`/health`. You should see `{"status":"ok"}`.

The admin account is created on the first start. After that, the bootstrap
values never change it, so you can clear them. To reset a password later, run
`python -m apps.api.scripts.create_user` locally with `DATABASE_URL` set to the Neon string.

Email: without `SMTP_USERNAME` / `SMTP_PASSWORD`, approved emails are written
to Render's log instead of being sent. Add `SMTP_SERVER`, `SMTP_PORT`,
`SMTP_USERNAME`, `SMTP_PASSWORD` and `SMTP_FROM` in **Environment** to send for real.

## 3. Keep-awake Worker: Cloudflare

1. In `infrastructure/cloudflare/keepalive/wrangler.toml`, set `BACKEND_URL` to
   **API_URL** (no trailing slash), then commit and push.
2. Sign up at https://dash.cloudflare.com (no card needed for Workers).
3. **Workers & Pages** → **Create** → **Import a repository**, pick the
   LeadForge repo, and use:

   | Setting | Value |
   |---|---|
   | Project name | `leadforge-keepalive` (must match `name` in its `wrangler.toml`) |
   | Build command | leave empty |
   | Deploy command | `npx wrangler deploy` |
   | Root directory | `infrastructure/cloudflare/keepalive` |

   Or from a terminal: `cd infrastructure/cloudflare/keepalive`, then
   `npx wrangler login` and `npx wrangler deploy`.
4. Open the Worker's `*.workers.dev` URL. You should see `{"ok":true,...}`.
   It now pings the API every 10 minutes (check **Settings → Trigger events**
   shows the cron `*/10 * * * *`).

## 4. Dashboard: Vercel

1. In the **lead-forge-u97p** project, open **Settings → Environment Variables**
   and add, for Production and Preview:

   | Key | Value |
   |---|---|
   | `NEXT_PUBLIC_API_BASE` | **API_URL** (no trailing slash) |
   | `NEXT_PUBLIC_SITE_URL` | `https://lead-forge-u97p.vercel.app` |

2. **Deployments** → **⋯** on the latest → **Redeploy**. `NEXT_PUBLIC_` values
   are built into the app, so a new build is required.
3. Keep **Root Directory** = `apps/dashboard`.

## 5. Test it

1. Open https://lead-forge-u97p.vercel.app and sign in with the bootstrap admin.
2. **Integrations** should show PostgreSQL and Google Gemini as Connected.
3. Send a test lead with the service key (copy `SERVICE_API_KEY` from Render →
   Environment):

   ```powershell
   $body = '{"company_name":"Acme","domain":"acme-test.com","industry":"saas","employee_count":80,"full_name":"Jane Test","title":"VP Marketing","email":"jane@acme-test.com"}'
   Invoke-RestMethod -Method Post -Uri "<API_URL>/leads/ingest" -Headers @{ "X-API-Key" = "<SERVICE_API_KEY>" } -ContentType "application/json" -Body $body
   ```

4. In **Pipeline**, open the lead and run research → score → draft, then approve
   it in **Approvals**.

## Updating later

`git push` to `main`. Vercel rebuilds the dashboard, and Render rebuilds the
API when anything under `apps/api/` changes (it also applies new migrations on
start). The keep-awake Worker redeploys too if it was set up from the repo.

## If something goes wrong

| Symptom | Fix |
|---|---|
| Dashboard shows "Starting the server…" for a long time | The API was asleep or is redeploying. Wait about a minute. If it happens often, open the keep-awake Worker's URL (step 3.4). |
| "Can't reach the LeadForge API" right away, or a CORS error in the browser console | `CORS_ORIGINS` in Render must exactly match the dashboard URL, and `NEXT_PUBLIC_API_BASE` in Vercel must be **API_URL**. Redeploy Vercel after changing it. |
| Render deploy fails at "Migration failed" | The log line says why. Usually a mistyped `DATABASE_URL`. |
| Sign-in says the password doesn't match | The bootstrap admin is only created if that email doesn't exist yet. Reset it with `create_user` (step 2). |
| Integrations shows Google Gemini "Not set up" | Set `GEMINI_API_KEY` in Render. |

## Free-plan limits

- **Render:** 750 free hours a month, enough for one service running nonstop.
  Keeping a free service awake on purpose is a grey area with Render, so this
  setup suits demos and early use, not anything critical. About 0.1 CPU, so AI
  steps can take several seconds.
- **Neon:** sleeps when unused and wakes in under a second; 0.5 GB of data.
  The keep-awake ping only hits `/health`, which doesn't touch the database.
- **Cloudflare Workers:** 100,000 requests a day free; the ping uses 144.
